# KineLab Motion joint alignment and latency plan

Baseline: Clearcam `0ae0ce4`. Scope: single-camera, browser-based tracking. Start with knee alignment in squats and sit-to-stand, then verify hip, ankle, shoulder, lunges, and single-leg balance separately.

## Recommendation

Keep MediaPipe as the baseline. First measure how far the skeleton lands from the joint on the displayed video, how far its angle is from a matching reference, and how old the pose is when drawn. Compare Direct and Adaptive input on the same clips while testing confidence and view selection on the same detections. Move inference to a worker if it still blocks drawing after simpler changes. Consider an offline model or a second camera if the remaining problem is depth accuracy.

## What the baseline establishes

- The live path already uses two-dimensional One Euro/outlier filtering, world-landmark smoothing and bone-length stabilization, view-dependent knee/hip blending, and frame-paced inference. Overlay interpolation or prediction runs at display cadence. Offline analysis already applies zero-phase smoothing. [Live pipeline](../../../apps/kinelab-motion/src/app.mjs#L647) · [Offline pipeline](../../../apps/kinelab-motion/src/sessions/offline-analysis.mjs)
- Running `node apps/kinelab-motion/bench/accuracy-bench.mjs` reproduced knee angle RMSE of 3.2° side-on and 10.5° front-on for the current view-blend benchmark variant. Forced 2D with best-leg selection had 3.2° and 45.3° at those views. At 45°, view-blend RMSE was 10.6°. These are five-seed synthetic results. The Kinect check measures squat counts from supplied skeleton data and bypasses camera pose inference. [Benchmark](../../../apps/kinelab-motion/bench/accuracy-bench.mjs) · [Validation record](../../../apps/kinelab-motion/docs/validation.md)
- A separate simulation drove the actual interpolator with a clean synthetic joint at 30 Hz, 25 ms fixed result delay, and 120 Hz drawing for six seconds. With the first second discarded, the 0 ms and 40 ms prediction settings gave horizontal RMS error of 2.57% and 0.56% of image width on a 0.5 Hz sinusoid. On a 1 Hz triangle wave, RMS improved from 4.34% to 1.89%, while maximum error increased from 4.86% to 6.23%. A 20 ms setting produced 2.23% RMS and 4.91% maximum on the triangle. The current predictor also raises chase speed when velocity is available, so the next experiment should compare fast chase alone against extrapolation at that same chase speed. This simulation used exact joint samples, with no camera, MediaPipe, or render compositor. [Interpolator](../../../apps/kinelab-motion/src/filters/pose-interpolator.mjs#L76)

## 1. Build a repeatable measurement

**Reference clips.** Start with OpenCap LabValidation squat and sit-to-stand videos and corresponding marker-based reference kinematics. Feed each camera independently. Use available frontal and oblique clips, then add a true side view and fast reversals using consented reference recordings or an eligible dataset. Fit3D offers synchronized RGB and Vicon-derived exercise data behind an account. REHAB24-6 offers projected and 3D joint references for arms, lunges, and squats under academic/nonprofit noncommercial terms. Check dataset terms and availability before downloading or using clips. Use one participant split across all views and trials, and bootstrap by participant. [OpenCap data and validation](https://doi.org/10.1371/journal.pcbi.1011462) · [LabValidation replay script](https://github.com/opencap-org/opencap-core/blob/main/ReproducePaperResults/labValidationVideosToKinematics.py) · [Fit3D dataset](https://fit3d.imar.ro/fit3d) · [REHAB24-6 dataset](https://zenodo.org/records/13305826)

**Three scores.** Measure overlay joint-center error in pixels and as a fraction of body height at the displayed frame. Verify CSS crop, aspect, mirroring, and rotation with known points before blaming the detector. Measure per-joint angle MAE, bias, limits of agreement, peak error and timing, and valid-frame/rep coverage. Compare like geometry: an image-plane or trunk–thigh proxy needs a projected or equivalently defined reference, while an anatomical rotation needs matching axes and conventions. Use an independent sync event or known timestamps and the existing fixed-lag option. Estimate and report phase lag separately, since cross-correlation can absorb filter delay. [Reference alignment](../../../apps/kinelab-motion/src/validation/align.mjs#L45) · [Validation CLI](../../../apps/kinelab-motion/bench/validate.mjs) · [ISB joint-coordinate conventions](https://pubmed.ncbi.nlm.nih.gov/11934426/)

**Instrument by frame.** Carry source frame ID, session/model generation, capture time or labeled fallback, and separate timestamps for input preparation, inference, analysis, recording, and canvas submission. Track p50/p95 stage latency, age of the pose drawn, inter-pose gaps, coverage, and reacquisition. Distinguish intentional skip, missed presentation callback, busy/stale worker result, and no valid pose. The existing inference timer includes canvas staging, the landmark timer stops at raw SDK return, and the overlay timer records submission. Compute HUD percentiles at the HUD cadence and retain cheap counters for adaptive decisions. Mark when actual capture time is missing. Use an external high-speed recording for physical motion-to-overlay timing on representative devices. [Current counters](../../../apps/kinelab-motion/src/tracking/performance-monitor.mjs#L107) · [Camera frame callback spec](https://wicg.github.io/video-rvfc/)

| Use 2D everywhere, or 3D everywhere | Keep both as controls for current Auto. At matched coverage, test per-joint/exercise source selection with near-side hysteresis, view stability, presence/visibility, projected limb length, and tracking residuals. The view estimator retains its last angle when fresh landmarks are absent, and its frontal 2D weight is currently unused in the angle blend. Test stale-view expiry and shoulder abduction from the front as independent changes. ## 3. Choose on held-out results

Device matrix: Android Chrome on a lower-end phone, iPhone Safari, and desktop Chrome/Firefox. Repeat a fixed warm clip per configuration, then run live acquisition, near/far framing, occlusion/recovery, and a sustained run with recording both off and on. Log negotiated camera settings, actual inference and render cadence, and browser/device/model/delegate. Profile optional overlays and recording separately if they dominate the trace.

Proposed adoption criteria, to finalize after baseline variance is known:

- **Quality:** Compare at equal 90% valid-frame coverage when both candidates can reach it, and report the whole error–coverage curve. Seek at least 20% fewer knee errors over 10° or at least 2° lower peak-angle MAE, with per-view results and no meaningful rep-count regression. Count missing measurements and lost peaks. Published MediaPipe target-frame squat results illustrate why: 8.78° RMSE on 71 of 75 retained peaks versus 25.43° with all outputs included, against a Kinovea 2D reference. [Primary study](https://rehab.jmir.org/2026/1/e102399/)
- **Filtering:** Seek at least 25% less static jitter with no more than one extra source frame of live peak delay and no more than 1° added peak bias. Require lower tail alignment error at reversals or occlusion recovery before increasing prediction.
- **Speed:** Seek at least 15% lower p95 pose age at canvas submission in the affected device tier, with comparable valid-pose coverage, peak-angle error, and rep accuracy. For a worker, also require fewer late render frames and a functioning fallback. Set noninferiority margins from repeat-run variation before looking at the held-out set.

Implementation order: baseline clip runner and stage timing → paired input/delegate A/B and offline confidence/view ablations → best small changes behind a flag → worker or new model only where measured bottlenecks remain. This investigation ran synthetic benchmarks. The real-video and real-device comparisons are the first implementation milestone.
